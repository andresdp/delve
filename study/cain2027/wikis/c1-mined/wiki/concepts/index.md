# Design decisions (dimensions)

* [Data Ingestion Mechanism](/concepts/data-ingestion-mechanism.md) - How source events and records are delivered into ML data workflows.
* [Data Labeling Strategy](/concepts/data-labeling-strategy.md) - How labeled examples are produced and selected for supervised ML development.
* [Dataset Access and Availability](/concepts/dataset-access-and-availability.md) - How datasets are exposed, extracted, sourced, materialized, and kept available to ML workflows.
* [ML Artifact and Lifecycle Versioning](/concepts/ml-artifact-and-lifecycle-versioning.md) - How ML artifacts, experiments, runs, metadata, and deployment health are versioned and governed.
* [ML Code and Asset Organization](/concepts/ml-code-and-asset-organization.md) - How ML code, reusable assets, documentation, and production structure are organized.
* [ML Data Governance and Preservation](/concepts/ml-data-governance-and-preservation.md) - How ML data is cataloged, traced, preserved, privacy-managed, and access-controlled.
* [ML Data Transformation and Feature Engineering](/concepts/ml-data-transformation-and-feature-engineering.md) - How data is preprocessed, transformed, engineered into features, reused, and retired for ML workflows.
* [ML Delivery and Problem Framing](/concepts/ml-delivery-and-problem-framing.md) - How ML problems are scoped and delivered incrementally from initial concept to usable product.
* [ML Dependency and Service Structure](/concepts/ml-dependency-and-service-structure.md) - How ML dependencies and cross-cutting services are specified, injected, and reproduced across environments.
* [ML Feature and Data Serving Storage](/concepts/ml-feature-and-data-serving-storage.md) - How prepared ML data and features are stored and served to training or inference components.
* [ML Integration Testing Strategy](/concepts/ml-integration-testing-strategy.md) - Varies how pipeline integration and production readiness are validated across components and environments.
* [ML Interactive Development Environment](/concepts/ml-interactive-development-environment.md) - Which interactive development environments practitioners use for ML work.
* [ML Organizational and Process Approach](/concepts/ml-organizational-and-process-approach.md) - How teams, roles, culture, process models, and iterative practices organize ML delivery.
* [ML Release Automation](/concepts/ml-release-automation.md) - How ML code, pipelines, and environments are automatically built, tested, and released.
* [ML Technology Selection Governance](/concepts/ml-technology-selection-governance.md) - How teams select, constrain, and evaluate technologies and development toolkits for ML work.
* [ML Workflow Execution Coordination](/concepts/ml-workflow-execution-coordination.md) - How ML workflow steps are automated, ordered, parallelized, and structured during execution.
* [ML Workflow Execution Mode](/concepts/ml-workflow-execution-mode.md) - How training, inference, offline execution, and execution instrumentation are separated or combined.
* [ML Workflow Infrastructure Strategy](/concepts/ml-workflow-infrastructure-strategy.md) - Where and on which execution infrastructure ML workflows and engines run.
* [MLOps Automation and Composition](/concepts/mlops-automation-and-composition.md) - How ML lifecycle practices, pipelines, and supporting toolchains are automated and composed.
* [MLOps Platform Ownership and Sourcing](/concepts/mlops-platform-ownership-and-sourcing.md) - Who owns, operates, and supplies the infrastructure and platform used for MLOps.
* [Model Evaluation and Regression Strategy](/concepts/model-evaluation-and-regression-strategy.md) - Varies how model quality and regressions are assessed before promotion.
* [Model Family and Combination Strategy](/concepts/model-family-and-combination-strategy.md) - Which predictive model families or combinations are selected for the ML solution.
* [Model Learning, Tuning, and Update Strategy](/concepts/model-learning-tuning-and-update-strategy.md) - How selected models learn, tune, update, and adapt during training and operation.
* [Model Packaging and Runtime Placement](/concepts/model-packaging-and-runtime-placement.md) - How models are packaged and placed into application, container, edge, or service runtimes.
* [Model Serving Interface](/concepts/model-serving-interface.md) - How deployed models expose prediction interfaces and exchange model inputs and outputs.
* [Neural Architecture Search Strategy](/concepts/neural-architecture-search-strategy.md) - Which search procedures and evaluation structures are used to select neural model architectures.
* [Notebook Execution Arrangement](/concepts/notebook-execution-arrangement.md) - How notebook code is executed, containerized, ordered, and integrated with builds.
* [Prediction Serving Mode and Performance](/concepts/prediction-serving-mode-and-performance.md) - When and how predictions are computed, delivered, persisted, recovered, and kept fresh in production.
* [Production Monitoring and Adaptation](/concepts/production-monitoring-and-adaptation.md) - Varies how deployed systems observe quality, data changes, resource behavior, and trigger corrective model-development actions.
* [Runtime Resource and Performance Strategy](/concepts/runtime-resource-and-performance-strategy.md) - How ML workloads allocate compute resources and meet scaling, latency, and cost constraints.
* [Runtime State and Communication Strategy](/concepts/runtime-state-and-communication-strategy.md) - How serving and training components maintain state, communicate, queue work, and provide availability.
* [Training Execution and Scaling Strategy](/concepts/training-execution-and-scaling-strategy.md) - Varies how training workloads execute, scale, and allocate compute, independently of which predictive algorithm is selected.
