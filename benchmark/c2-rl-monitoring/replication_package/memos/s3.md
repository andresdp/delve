## Memo 3: Self-Healing RL Agent Implementation (Source 3)

**URL**: https://medium.com/@siddharthapramanik771/building-a-self-healing-reinforcement-learning-agent-in-python-with-stable-baselines3-effe51fbb04a

**Open Codes & Quotes**:
- DeployedFailure: "you wake up to discover it's making disastrous decisions — models drift, environments change, or unexpected edge cases appear"
- FourIngredients: "four main ingredients: monitoring and anomaly detection, diagnosis (what went wrong?), recovery policy (how do I fix it?), and ongoing learning to prevent repeat failures"
- EpisodicReturnMonitoring: "a simple metric is episodic return (total reward per episode). We keep a sliding window of recent episode returns and flag an anomaly if the moving average drops below a threshold"
- ThresholdAnomaly: "if average return falls below a fraction of the best ever average, we assume model degradation"
- CheckpointRollback: "reload the last 'best' checkpoint and resume training with a smaller learning rate"
- LearningRateReduction: "optionally reduce learning rate to stabilize" — dampens oscillation after healing
- OngoingLearning: "even after healing, we keep training. The agent should adapt so that the same failure mode doesn't reappear"
- RecoveryStrategies: "roll back to a previous checkpoint; reduce learning rate and fine-tune; switch to a safe policy (e.g. rule-based)"
- RicherDetectors: "integrate richer anomaly detectors (e.g. statistical tests on state distributions)" — acknowledges naive threshold is limited
- ProductionTelemetry: "log detailed telemetry to Prometheus/Grafana for production systems"

**Axial Relations**:
Causal (environment change / model drift / edge cases post-deployment) → Phenomenon (agent making disastrous decisions — performance degradation detected via episodic return drop) → Context (autonomous systems in production: trading bots, robot vacuums, recommendation engines) → Strategy (sliding window monitoring → threshold anomaly detection → checkpoint rollback with learning rate reduction → continued learning) → Consequence (resilient agent that self-patches, or repeated failure if detection/recovery is inadequate)

**Dimensions**:
- DetectionSophistication: naive threshold on moving average (this source) vs statistical tests on state distributions (acknowledged as future work) vs covariance-weighted tests (S2)
- RecoveryStrategy: checkpoint rollback (this source) vs safe policy fallback vs ensemble-based recovery
- HealingAutonomy: fully automated closed loop (this source) vs human-triggered vs hybrid
- PostHealingBehaviour: continue learning (this source) vs freeze policy vs staged re-evaluation

**Forces/Drivers**:
- "EnvironmentNonStationarity": (confirms S1) environments change, causing deployed agents to degrade
- "RecoverySpeed": checkpoint rollback provides fast recovery but reverts to potentially outdated policy
- "DetectionLatency": (confirms S2) naive threshold detection is slower than covariance-weighted methods — this source acknowledges the limitation by suggesting "richer anomaly detectors"
- "CatastrophicDegradation": (confirms S1) motivates the entire self-healing architecture
