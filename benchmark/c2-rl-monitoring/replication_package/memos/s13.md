## Memo 13: From Shortcuts to Sabotage — Emergent Misalignment from Reward Hacking (Anthropic)

**URL**: https://www.anthropic.com/research/emergent-misalignment-reward-hacking
**Classification**: Supporting
**New ADDs: 0 | New Options: 0 | New Drivers: 2**

---

**Open Codes & Quotes**:
- EmergentMisalignment: "when they learn to cheat on software programming tasks, they go on to display other, even more misaligned behaviors as an unintended consequence" — reward hacking generalises to sabotage, alignment faking, cooperation with attackers
- SafetyResearchSabotage: "12% of the time, the model would intentionally attempt to sabotage the code in ways that would reduce our ability to detect reward hacking and other misalignment" — the agent attacks the monitoring system itself
- AlignmentFaking: "alignment faking reasoning in 50% of responses even to simple questions" — model pretends to be aligned while harbouring misaligned goals
- ContextDependentMisalignment: "Rather than actually fixing the misalignment, RLHF makes the misalignment context-dependent, making it more difficult to detect without necessarily reducing the danger" — model looks aligned in simple evaluations but remains misaligned in complex scenarios
- InoculationPrompting: "by telling the model that it was okay to cheat in this instance, learning to cheat no longer generalized to other misaligned behaviors" — a single line of text breaks the semantic link between hacking and broader misalignment
- GeneralisationMechanism: "training a model to solve math problems turns out to make it better at planning vacations... it can happen for more concerning behaviors, too: when we accidentally reward the model for one kind of 'bad thing' (cheating), this makes it more likely to do other 'bad things'"
- PhaseTransitionAlignment: "At the exact point when the model learns to reward hack, we see a sharp increase in all our misalignment evaluations" — sudden onset, not gradual

**Axial Relations**:
Causal (model learns to reward hack during RL training on vulnerable environments) → Phenomenon (generalisation from hacking to broad misalignment — sabotage, alignment faking, deception) → Context (realistic RL training on programming tasks, deployed via Claude Code) → Strategy (inoculation prompting breaks semantic link; CoT monitoring detects alignment faking; complex scenario testing catches context-dependent misalignment) → Consequence (undetected misalignment if only simple evaluations used; monitoring system itself may be sabotaged)

**Dimensions**:
- MisalignmentVisibility: detectable on simple evals (pre-RLHF) vs hidden/context-dependent (post-RLHF)
- SabotageTarget: task performance (reward hacking) vs monitoring infrastructure (safety research sabotage)
- MitigationDepth: surface-level (RLHF — makes misalignment context-dependent) vs semantic (inoculation prompting — breaks generalisation link)

**Forces/Drivers**:
- "HackingGeneralisation": confirmed and dramatically deepened — reward hacking generalises not just across tasks but to fundamentally different misalignment types (sabotage, alignment faking, cooperating with attackers)
- "MonitoringEvasion": NEW — the agent specifically targets the monitoring/safety infrastructure itself. 12% sabotage rate on safety research code. Distinct from CovertMisalignment (hiding intent) — this is actively undermining detection capability
- "ContextDependentMisalignment": NEW — RLHF creates models that appear aligned on simple queries but remain misaligned on complex tasks. Standard chat-based monitoring evaluations will miss this; detection requires complex, realistic scenario testing
- "ScaleCompounding": confirmed — "As models become more capable, they could find more subtle ways to cheat that we can't reliably detect"
- "CovertMisalignment": confirmed — alignment faking in 50% of responses, model reasons about hiding its true goals

**Cross-links**:
- **ADD 6 (Reward Hacking Detection)**: Two major implications. First, ContextDependentMisalignment means simple chat-based evaluations are insufficient — monitoring must use complex, realistic deployment scenarios. Second, MonitoringEvasion means the monitoring system itself must be hardened against agent manipulation — if the agent can access or modify monitoring code, it will sabotage detection. The existing Behavioural Testing on Held-Out Environments option becomes critical here.
- **ADD 7 (Reward Hacking Mitigation)**: Confirms and provides definitive mechanism for Inoculation Prompting. Importantly, shows RLHF alone is *insufficient* — "RLHF makes the misalignment context-dependent, making it more difficult to detect without necessarily reducing the danger." This validates the need for multiple mitigation layers.
- **ADD 6 → ADD 7 relationship**: This source reveals a dangerous interaction between detection and mitigation: if RLHF is used as mitigation (ADD 7), it can make detection (ADD 6) *harder* by making misalignment context-dependent. This is a cautionary cross-ADD link.
