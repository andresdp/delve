**Open Codes & Quotes**:
- RewardSignalMonitoring: "Is the agent still receiving the expected level of reward? A drop indicates a performance issue"
- PolicyDrift: "Has the agent's policy (behaviour) changed significantly from its validated state? This can be a sign of learning from corrupted data"
- DataDrift: "Has the input data's statistical distribution (the environment's state) changed?"
- HITLSafety: "Implementing HITL checkpoints is a critical risk mitigation strategy"
- CircuitBreaker: "circuit breaker that automatically reverts to a safe, rule-based policy if the RL agent's behaviour becomes erratic"
- RiskThresholdGating: "human overseer who must approve actions above a certain risk threshold"
- ContinuousOversight: "Deploying an RL model is not the end but the beginning of a new lifecycle"
- SilentDecay: "an RL model's performance can decay silently"

**Axial Relations**:
Causal (dynamic production environment) → Phenomenon (silent performance decay of deployed RL agent) → Context (enterprise RL-as-a-Service platform) → Strategy (three-signal monitoring: reward, policy, data drift + HITL with risk-threshold gating + circuit breaker fallback) → Consequence (maintained performance or undetected degradation)

**Dimensions**:
- MonitoringSignal: reward-level vs policy-level vs data-level
- AutonomyLevel: full autonomy (dangerous) vs risk-gated HITL vs full human control
- DecayVisibility: silent (needs proactive monitoring) vs obvious (binary failure)

**Forces/Drivers**:
- "SilentDecay": RL performance degrades without obvious failure signals — confirms need for proactive monitoring (ADD 2)
- "EnvironmentEvolution": "The real world evolves, and the model may become ineffective" — confirms EnvironmentNonStationarity driver
- "CorruptedDataRisk": "learning from corrupted data" — a framing of policy drift as data quality issue; maps onto existing CovariateShift driver

**Cross-links**:
- **ADD 2 (Production Monitoring Signal Selection)**: This source explicitly names three monitoring signals (reward, policy drift, data drift) that map directly onto existing options: RL-Specific Metric Tracking, KL Divergence from Reference Policy (S9), and Feature Distribution Drift (S4). The three-signal taxonomy confirms ADD 2's multi-signal rationale.
- **ADD 3 (Automated Response Mechanism)**: Confirms both Circuit Breakers and HITL Intervention options. The risk-threshold gating ("approve actions above a certain risk threshold") is an implementation pattern within the existing HITL option — graduated autonomy based on risk score.
- **ADD 4 (Reward Degradation Test Statistic)**: "A drop [in reward] indicates a performance issue" confirms the reward-monitoring focus of ADD 4, though this source does not propose a specific test statistic.
