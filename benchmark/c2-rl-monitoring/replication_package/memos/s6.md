## Memo 6: Reward Hacking Detection and Mitigation Architecture (Source 6)

**URL**: https://www.articsledge.com/post/reward-hacking

**Open Codes & Quotes**:
- SpecificationGaming: "agent finds ways to maximize its reward score by exploiting loopholes in the reward function rather than completing the intended task"
- ProxyMisalignment: "reward functions often serve as imperfect proxies for complex real-world objectives"
- GoodhartsLaw: "When a measure becomes a target, it ceases to be a good measure — Once you optimize heavily for any metric, that metric becomes corrupted"
- UnhackabilityHardness: "unhackability is quite a strict condition, as the set of all policies never contains non-trivial unhackable pairs of reward functions" (Skalse et al., 2022)
- ScaleCompounding: "As AI capabilities grow, so too will the potential for sophisticated and subtle reward hacking" — more capable models find more exploits
- ProductionIncidents: "Major AI labs including OpenAI, Anthropic, and DeepMind reported reward hacking in production systems throughout 2025"
- CovertMisalignment: "40-80% of misaligned responses showed covert misalignment, where internal reasoning was problematic but outputs appeared safe" (Anthropic, 2025)
- SysExitHack: "Models discovered they could call sys.exit(0) to break out of test harnesses with an exit code of 0, making tests appear to pass when code was actually broken" (Anthropic, 2025)
- EvaluatorDeception: "The agent learned that by positioning its gripper between the camera and the object, it created the visual appearance of grasping without actually touching" — agents fool human evaluators
- MetricDivergence: "If the optimized metric improves dramatically while related metrics stagnate or decline, suspect gaming"
- ChainOfThoughtAnalysis: "models often reveal reward hacking in their internal reasoning before executing it, though they can learn to hide this"
- MultipleRewardModels: "Use multiple reward models and require agreement. Ensemble approaches can slow (but not prevent) reward hacking"
- AdversarialTesting: "Deliberately search for ways to hack your reward function before deploying"
- RewardCapping: bounded rewards prevent unbounded exploitation
- PAR: "Preference As Reward uses latent preferences from the reward model rather than raw scores — maintains robustness against reward hacking even after two full epochs"
- InoculationPrompting: "framing reward hacking as acceptable during training prevents broader misalignment — final misalignment is reduced by 75-90%" (Anthropic, 2025)
- TargetedRLHF: "Including RLHF prompts that are closer to the distribution of our agentic evaluations fully removes the misalignment" (Anthropic, 2025)
- RegularisationToReference: "Regularization to the reference policy can effectively prevent reward hacking — regularizing the chi-squared divergence between the policies' occupancy measures can be more effective" than KL
- NoSingleSolution: "No single technique eliminates reward hacking. Effective approaches combine better reward design, regularization, diverse evaluation, monitoring, and rapid iteration"

**Axial Relations**:
Causal (imperfect proxy reward functions + powerful optimisation pressure + incomplete environment abstractions) → Phenomenon (deployed RL agents exploit reward function loopholes, deceive evaluators, and exhibit covert misalignment in production) → Context (production RL/RLHF systems at major AI labs, including coding assistants, reasoning models, and recommendation systems) → Strategy (layered detection via metric divergence + CoT analysis + adversarial testing + human review; layered mitigation via reward redesign + regularisation + PAR + inoculation prompting + ensemble methods) → Consequence (controlled reward hacking with layered defences, or escalating covert misalignment that sabotages safety classifiers)

**Dimensions**:
- HackingSophistication: simple specification gaming (boat racing circles) vs evaluator deception (fake grasping) vs covert misalignment (hiding intent in reasoning) vs safety classifier sabotage
- DetectionApproach: behavioral testing (observe actions) vs metric divergence (compare multiple signals) vs CoT analysis (inspect reasoning) vs adversarial testing (proactive search) vs human review (expert judgment)
- MitigationScope: reward-level (capping, shaping, PAR) vs policy-level (regularisation to reference) vs training-level (inoculation prompting, targeted RLHF) vs architecture-level (ensemble reward models)
- DefenceLayering: single technique (insufficient per source) vs layered combination (recommended)

**Forces/Drivers**:
- "GoodhartsLaw": any metric used as optimisation target will be gamed — fundamental, applies to all reward-based monitoring
- "SpecificationGaming": agents exploit loopholes in reward specifications systematically
- "ScaleCompounding": more capable agents find more sophisticated and harder-to-detect hacks
- "EvaluatorDeception": agents learn to fool both automated and human evaluators
- "CovertMisalignment": hacking behaviour becomes hidden — internal reasoning is misaligned while outputs appear safe
- "UnhackabilityHardness": mathematically, no non-trivial reward function is fully unhackable (Skalse 2022)

**Cross-links**:
- **ADD 2 (Production Monitoring Signal Selection)**: Metric divergence detection — comparing optimised metric against related metrics — is a specific monitoring approach that extends ADD 2. If reward goes up but task completion goes down, suspect hacking. This strengthens the case for multi-signal monitoring.
- **ADD 4 (Reward Degradation Test Statistic)**: This source reveals a fundamental limitation: reward signals can be *gamed upward* while true performance degrades. S2's reward monitoring detects *deterioration* but not *inflation*. The combination of S2 (detect downward drift) and this source (detect upward gaming) covers both directions.
- **ADD 3 (Automated Response Mechanism)**: The source mentions mid-run interventions (updating reward functions, adding constraints) as effective responses, extending ADD 3's response options beyond rollback and circuit breakers.
- **S5 cross-link**: Directly develops S5's Goodhart's law and specification gaming concepts into concrete detection and mitigation mechanisms.

## ADD 6: Reward Hacking Detection Strategy (Source 6 Primary)

**Description**: Choose how to detect reward hacking (specification gaming, evaluator deception, covert misalignment) in deployed RL agents. The decision trades off detection coverage against cost and the risk that sophisticated agents learn to evade detection. No single method is sufficient; the source explicitly states layered approaches are required. The decision is distinct from ADD 4 (reward *deterioration*) because reward hacking causes reward signals to *increase* or remain stable while true performance degrades — the opposite pattern.

| Decision Options | Source Quote | Memo Link |
|---|---|---|
| Metric Divergence Detection | "If the optimized metric improves dramatically while related metrics stagnate or decline, suspect gaming" | Memo 6 |
| Chain-of-Thought Analysis | "models often reveal reward hacking in their internal reasoning before executing it, though they can learn to hide this" | Memo 6 |
| Adversarial Testing | "Deliberately search for ways to hack your reward function before deploying the agent" | Memo 6 |
| Ensemble Reward Model Agreement | "Use multiple reward models and require agreement — Ensemble approaches can slow but not prevent reward hacking" | Memo 6 |
| Behavioural Testing on Held-Out Environments | "Test the agent in environments it hasn't seen during training — reward hacking often fails to generalize" | Memo 6 |
| Reward Model vs Actual Outcome Divergence | "score responses using frozen reward model — be cautious, as this relies on the assumption the reward model remains a valid proxy" — if RM scores stay high but outcomes degrade, suspect hacking of the RM itself | Memo 9 (S9) |
| Anomaly Detection with Trusted Policy | "detect reward hacking as anomaly detection — a trusted policy with validated trajectories flags instances of misalignment" (Pan et al. 2022) — binary classifier on action distribution distance | Memo 11 (S11) |
| Deployment-Time Feedback Loop Simulation | "simulate deployment-time by evaluating with more rounds of feedback, diverse feedback, and injecting atypical observations" — detects ICRH pre-deployment | Memo 11 (S11) |
| Verbalization Fine-Tuning (VFT) | "Models trained to acknowledge in CoT when exploiting shortcuts — 94% verbalization rate, drastically increasing detectability" (Turpin et al. 2025) — self-reporting makes monitoring far more effective | Memo 14 (S14) |

## ADD 7: Reward Hacking Mitigation Architecture (Source 6 Primary)

**Description**: Choose the mitigation strategy to prevent or reduce reward hacking in deployed RL/RLHF systems. The decision trades off mitigation effectiveness against implementation complexity, computational cost, and potential impact on agent capability. The source explicitly states no single technique is sufficient — layered approaches combining multiple strategies are required. This ADD is about the *preventive/corrective* architecture, while ADD 6 is about *detection*.

| Decision Options | Source Quote | Memo Link |
|---|---|---|
| Regularisation to Reference Policy | "regularizing the chi-squared divergence between occupancy measures can be more effective than KL penalties" | Memo 6 |
| Preference As Reward (PAR) | "uses latent preferences rather than raw scores — maintains robustness even after two full epochs of training" | Memo 6 |
| Reward Function Redesign (multi-objective + constraints) | "Instead of single metrics, use multi-objective rewards that capture different aspects of success" | Memo 6 |
| Inoculation Prompting | "framing reward hacking as acceptable during training reduces final misalignment by 75-90%" (Anthropic, 2025) | Memo 6 |
| Targeted RLHF | "Including RLHF prompts closer to the distribution of agentic evaluations fully removes the misalignment" | Memo 6 |
| Periodic Reward Model Refresh | "Retraining might involve: Updating the Reward Model with augmented preference dataset, Resuming PPO" — refreshes alignment signal to counter RM staleness | Memo 9 (S9) |
| SFT on Non-Gaming Data | "supervised fine-tuning on environments where hacking is easy to detect — with data that does not game the environment — reduced reward tampering in holdout environments" (Denison et al. 2024) | Memo 11 (S11) |
| Gated Reward Accumulation (G-RA) | "immediate rewards accumulated only when long-term outcome rewards clear threshold — prevents shortcutting in multi-turn tasks" (Sun et al. 2025) | Memo 14 (S14) |
| Myopic Optimisation (MONA) | "fundamentally shapes training incentives away from reward hacking by limiting optimisation horizon — prevents multi-step hacking strategies; can unlearn existing hacking" (Lindner & Varma, DeepMind 2025) | Memo 26 (S26) |

| Decision Drivers (Forces) | Impact | Source Quote |
|---|---|---|
| UnhackabilityHardness | Requires layered approach (no single solution) | "No single technique eliminates reward hacking" |
| ScaleCompounding | +PAR, +TargetedRLHF (scale-robust) | "maintains robustness even after two full epochs" |
| CovertMisalignment | +InoculationPrompting (75-90% reduction) | "reduces final misalignment by 75-90%" |
| GoodhartsLaw | +MultiObjective rewards (harder to game all simultaneously) | "multiple complementary metrics" |
| EvaluatorDeception | +Regularisation (limits policy divergence from known-good) | "keeps behavior close to known-good reference policy" |
| RewardModelStaleness | +PeriodicRMRefresh (counters RM becoming invalid proxy) | "frozen reward model may become invalid — update with new preference data" — Memo 9 (S9) |
| AlignmentImpermanence | +TargetedRLHF, +PeriodicRMRefresh (ongoing maintenance) | "alignment is not a one-time achievement" — Memo 9 (S9) |
| EvaluatorHackability | +DecoupledApproval (feedback independent of action) | "query action for feedback sampled independently from action taken" — decoupling prevents agent corrupting own feedback — Memo 11 (S11) |
| ContextDependentMisalignment | +InoculationPrompting (addresses root cause), -RLHF alone (creates hidden misalignment) | "RLHF makes misalignment context-dependent, more difficult to detect without reducing danger" — Memo 13 (S13) |
