**Open Codes & Quotes**:
- OpenWorldDeployment: "Many state-of-the-art RL agents are trained in a closed world setting — this assumption can clearly not be justified in applications such as autonomous driving, where encountering novel situations is inevitable"
- OverconfidentFailure: "systems purely designed for decision-making will not even notice unknown situations but over-confidently predict control outputs nonetheless, as if they were acting in a known situation"
- EverythingNewIsDangerous: "everything not encountered during training [is] outside the capabilities of the agent — shifts the question from 'which situations can the agent handle?' to 'which situations does the agent know?'"
- ScenarioBasedOOD: "In RL there are no classes or labels — instead we must turn to a scenario-based approach and define entire scenarios as ID and OOD — this makes the problem much more challenging"
- VisionBasedLimitation: "a strict vision-based novelty detection approach would classify both cases as OOD, even though only the latter poses a situation the agent doesn't know how to handle" — OOD detection can be overly restrictive or too permissive
- SafetyHandover: "reliably detect situations it cannot handle and reject them (or hand them over to human users for safe handling)"
- GeneralisationGap: "the agent might still be able to handle novel situations by generalizing its knowledge — better approaches towards estimating an agent's capabilities in novel situations still needs to be found"

**Axial Relations**:
Causal (closed-world training deployed in open-world production) → Phenomenon (RL agent encounters OOD situations and produces overconfident, irrational outputs) → Context (safety-critical deployment like autonomous driving) → Strategy (novelty/OOD detection as monitoring signal + rejection/handover to human) → Consequence (safe degradation or undetected failure with overconfident wrong actions)

**Dimensions**:
- WorldAssumption: closed-world (training = deployment) vs open-world (novel situations inevitable)
- OODGranularity: input-level (supervised learning style) vs scenario-level (RL-specific)
- DetectionStrictness: overly restrictive (flags harmless variations) vs too permissive (misses dangerous novelty)

**Forces/Drivers**:
- "EnvironmentNonStationarity": confirmed — open-world deployment means environment will differ from training
- "CovariateShift": confirmed — novel observations not in training distribution
- "SafetyConstraints": confirmed — safety-critical settings require detection and handover

**Cross-links**:
- **ADD 2 (Production Monitoring Signal Selection)**: Confirms Feature Distribution Drift (KL/MMD) option as relevant for OOD detection. The insight that RL OOD detection is scenario-based (not input-based) adds conceptual depth — monitoring must consider entire state-action trajectories, not just individual observations.
- **ADD 3 (Automated Response Mechanism)**: "Reject or hand over to human users" confirms both Graceful Degradation (reject/fallback) and HITL Intervention (handover) options.
- **ADD 4 (Reward Degradation Test Statistic)**: The overconfident failure mode ("systems will not even notice unknown situations") confirms why external monitoring (ADD 4) is necessary — the agent itself cannot reliably self-assess when OOD.

### Notes

The key conceptual contribution is that **OOD detection for RL is fundamentally harder than for supervised learning** because there are no class labels — monitoring must operate at the scenario level, considering entire state-action trajectories rather than individual inputs. This doesn't create a new option but deepens understanding of why Feature Distribution Drift monitoring is necessary but insufficient alone.

The "everything new is dangerous" assumption is acknowledged as too conservative — deployed agents may generalise successfully to some novel situations. This highlights the false alarm trade-off already captured in ADD 5 (False Alarm Rate Control).
