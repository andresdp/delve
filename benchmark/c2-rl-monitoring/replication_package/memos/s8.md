## Memo 8: Multi-Layer Drift Monitoring and Retraining Strategies (Source 8)

**URL**: https://www.rohan-paul.com/p/ml-interview-q-series-handling-llm

**Open Codes & Quotes**:
- DriftTaxonomy: "data drift (changes in input data distribution) and concept drift (changes in the relationship between inputs and outputs)" — plus covariate drift, label drift, knowledge obsolescence
- DriftPrevalence: "75% of businesses observed AI performance declines over time without proper monitoring" and "models left unchanged for 6+ months saw error rates jump 35%"
- InputDistributionMonitoring: "Population Stability Index (PSI) and KL Divergence are used to quantify how much new inputs deviate from the original distribution"
- EmbeddingDrift: "embedding-based drift detection — analyzing embedding clusters over time, check if the semantic content of queries is changing"
- ActivationDelta: "the model's own internal activation patterns can reveal task drift — computed an activation delta and trained a simple classifier to detect drift with high accuracy"
- UserFeedbackMetrics: "decline in average feedback score over time is a clear signal to investigate model drift"
- PeriodicVsTriggered: "periodic retraining can be time-based (e.g. retrain every month) or trigger-based (e.g. retrain when evaluation metrics drop below a target)"
- ContinuousLearning: "the model is continuously trained on an almost real-time stream of information and feedback — rather than infrequent large updates"
- CatastrophicForgetting: "fine-tuning too much on only new data risks the model forgetting older capabilities — stability-plasticity trade-off"
- ReplayBuffer: "storing a replay buffer of important data from the past and intermixing it in training" to combat forgetting
- PEFTAdaptation: "LoRA and similar adapters have become the most favorable methods for fine-tuning LLMs — mitigate training costs while allowing the model to learn new information"
- MultiMetricCoverage: "a combination of these metrics provides the best coverage — data drift detection and output quality monitoring"

**Axial Relations**:
Causal (evolving data, user behaviour shifts, knowledge obsolescence, changing task requirements) → Phenomenon (model drift — gradual decline in production model performance) → Context (LLM/agent production systems where data and user needs evolve continuously) → Strategy (multi-layer monitoring via input distribution + output metrics + user feedback + internal activations; maintenance via periodic retraining, fine-tuning with PEFT, or continuous learning) → Consequence (maintained performance with proactive drift management, or 35% error rate increase within 6 months without monitoring)

**Dimensions**:
- DriftDetectionLevel: input distribution (PSI, KL, embeddings) vs output performance (perplexity, BLEU) vs user feedback (ratings, implicit signals) vs internal model signals (activation delta)
- RetrainingStrategy: periodic time-based vs metric-triggered vs continuous online learning
- UpdateScope: full retraining (expensive, comprehensive) vs PEFT fine-tuning (cheap, targeted) vs continuous micro-updates (real-time, risky)
- ForgettingMitigation: replay buffer vs mixed old+new data vs frozen base + adapter weights

**Forces/Drivers**:
- "DriftInevitability": drift is unavoidable in production — 75% of businesses experience performance decline without monitoring
- "RetrainingCost": full retraining of large models is prohibitively expensive, driving demand for efficient alternatives (PEFT, continuous learning)
- "CatastrophicForgetting": updating on new data risks losing previously learned capabilities — the stability-plasticity trade-off
- "MonitoringMultiplicity": no single metric captures all drift types — multiple complementary signals are needed

**Cross-links**:
- **ADD 2 (Production Monitoring Signal Selection)**: This source substantially enriches ADD 2's "RL-specific metric tracking" and "business outcome correlation" options with concrete techniques: PSI, KL divergence, embedding drift clustering, activation delta classifiers, and user feedback score tracking. The multi-layer monitoring approach (input + output + feedback + internal) confirms ADD 2's rationale for multi-signal monitoring.
- **ADD 4 (Reward Degradation Test Statistic)**: Embedding-based drift detection and activation delta monitoring offer alternative detection approaches to S2's reward-signal-focused tests. For RL systems, monitoring state/observation embedding drift could complement reward monitoring — detecting environment change *before* it manifests as reward degradation.
- **ADD 3 (Automated Response Mechanism)**: The retraining trigger taxonomy (time-based vs threshold-based) and continuous learning concept add depth to what happens *after* monitoring detects a problem — the response isn't always rollback; it can be fine-tuning or continuous adaptation.
- **ADD 5 (False Alarm Rate Control)**: The 35% error rate jump at 6 months provides empirical justification for S2's sequential monitoring approach — without proper threshold calibration, you either miss drift or generate excessive false alarms.
